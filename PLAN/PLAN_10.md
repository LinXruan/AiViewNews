# PLAN 10 — 预热、测试与验收准备

日期：2026-11-17　｜　阶段：M5

## 1. 需求

验收 = 60% 现场演示 + 口头问答，"系统不能运行或经常出错"直接不及格。本计划负责把演示变成一件没有风险的事。

## 2. 方案

**预热**（`scripts/warmup.py`）：依次检查——配置可读、SQLite 可写、**可用内存 ≥6GB**（低于阈值直接提示关掉大程序，mineru 要求 16GB 而本机常只剩 4GB 左右）、mineru 命令可用、模型权重已下载、样例 PDF 能解析、DeepSeek 能返回合法 JSON；每项输出耗时与结论，任一失败以非零码退出。演示前必须跑一遍并全绿。

**测试**（`tests/`，pytest）：每个用例用临时数据库与临时数据目录，**不得读写 `data/db.sqlite3`**，避免跑测试把演示数据搞坏。
- 配置：`settings` 读取优先级（库 > env > 默认）、key 掩码、空字符串不覆盖、越权 403。
- 契约：LLM 返回的三种结构校验与异常样例（含 ```json 包裹、缺字段、类型错）。
- 定位：`source_quote` 命中 / 未命中两种情况的 offset 结果。
- 状态机：并发上传后的状态推进、进程重启后的重置。
- 权限：未登录 401、普通用户访问 admin 403。
- 导出：DOCX 生成后能被 python-docx 重新读回。

**兜底数据**：预置 1 份已解析文档 + 1 个已完成任务（含事件与报告），放 `data/seed/`。若现场 mineru 或网络异常，直接切兜底数据继续演示。

**演示脚本**（3 分钟）：

- 现场**只冷解析 1 份**新 PDF，另外 2 份用预热好的已解析文档凑满"3 个文件同时上传"的展示。理由是解析串行队列下一个文件就要几十秒到两分钟，3 份冷解析必然超时。
- 顺序：上传 3 份（1 新 2 旧）→ 查询 → 任务变 done → 点时间线节点看详情 → 编辑报告并保存 → 导出 DOC → 切管理员看他人任务。

**文档**：中期报告（2026-12-11，≥1500 字）、课程设计报告（2027-01-22，待确认）、用户使用说明书、源码压缩包；报告内的架构图与 PLAN.md §4 保持一致，数据库 ER 图取自 PLAN_1 §2。中期材料直接由 M0/M1 的产物与 PLAN_1 契约支撑，**12 月初起草**，不要等 M2 完成。
