# PLAN 6 — 前端五区与轮询

日期：2026-11-17　｜　阶段：M0–M3　｜　状态：已实现

## 1. 需求

基本要求 §4.1 要求五个区域：文件上传区、查询事件区、分析任务列表区、时间线摘要区、报告预览区，可多界面。要求美观、交互强（占加分项）。

## 2. 方案

- 单页 + 顶部导航切换视图，避免多页状态丢失：`上传` / `任务` / `时间线` / `报告` /（管理员可见）`管理`。
- 布局：顶部标题栏（系统名 + 当前用户 + 登出）；左侧上传区固定，右侧内容区随导航切换；窄屏（<768px）单列堆叠。
- 上传区：`<input type=file multiple accept=.pdf>`，一次可选多个；每个文件一行进度与状态徽标（待解析/解析中/已解析/失败），失败行显示原因。上传进度用 `XMLHttpRequest.upload.onprogress`——`fetch` 拿不到上传百分比，大文件会看起来像卡死。
- 查询区：文本框 + 文档多选（默认全选已解析文档）+ 提交；提交后立即出现一条任务记录。
- 任务列表：表格列＝**查询内容、事件数量、事件名称、查询时间、任务状态**（需求 §4.4 的五个字段，一个不能少）+ 耗时；事件名称取 `event_titles` 前 3 条，超出显示"等 N 条"。状态用色块，`analyzing` 时行内显示轮询指示。
- 轮询：`setInterval` 1.5s，只在任务视图可见且存在未完成任务时运行，`document.hidden` 时暂停。列表接口只返回最近 50 条 + 总数；单任务详情单独轮询 `/api/tasks/{id}`，不要每 1.5 秒把历史全表拉一遍。
- 安全：所有用户/模型文本用 `textContent` 写入；报告 HTML 来自服务端白名单渲染，不使用 `innerHTML` 拼接原始数据。
- 不引入前端框架与 CDN，保证断网也能演示。
