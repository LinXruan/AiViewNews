# PLAN 7 — 时间线摘要与事件详情

日期：2026-11-17　｜　阶段：M3　｜　状态：已实现

## 1. 需求

基本要求 §4.5：按时间顺序展示事件节点与时间线摘要。选做 3：点击节点展示事件详情。第 14 页给了水平与竖向两种样式。

## 2. 方案

- 主视图用**水平时间线**：一条轴 + 按 `event_time` 升序排列的节点（日期 + 一句话摘要）。
- 窄屏自动切**竖向时间线**：同一条数据换 CSS 布局，不重写结构。
- `event_time` 为 null 的事件不进轴线，收在末尾「时间不详」分组里，不能丢。
- 顶部固定展示 `tasks.timeline_summary` 全文。
- 点击节点 → 右侧抽屉/下方面板显示：事件全文、来源文档名、页码（由后端用 `page_offsets` 反查，不采信模型）、`source_quote` 原文片段；`source_offset` 非空时在「原文视图」中把该片段标黄。
- **溯源取舍**：不做内嵌 PDF.js 高亮。理由：本机内存吃紧、工期短，而 REQUIREMENT 只要求"原文高亮位置信息用于前端溯源"。改为「md 原文视图 + 标黄 + 页码 + PDF 下载链接」，功能可演示、成本低一个量级。此偏差需在 REQUIREMENT 偏差段记录。
- **后期补强的最低成本路径**：如果时间富余，不再算字符偏移，而是用 PDF.js 的文本搜索功能直接用 `source_quote` 定位并画高亮层。坐标换算这一整块可以完全绕开，是性价比最高的升级方式。这也是口头问答里最可能被追问的点，先想好怎么答。

## 3. 文件

- 新增 `web/views/timeline.js`、`app/api/documents.py` 增加 `GET /api/documents/{id}/text`（返回 parsed_md 分页切片，供原文视图）。
- 修改 `web/style.css`、`web/app.js`。

## 4. 验证

1. 一条查询结果里 5 个节点按日期升序，日期文本正确。
2. 点击任一节点出详情，页码与原文片段一致；标黄位置与片段吻合。
3. 构造一个 `event_time=null` 的事件，落在「时间不详」组且可点开。
4. 375px 宽下自动变竖向，节点不重叠。
