# PLAN 9 — 管理员界面（选做 1）

日期：2026-11-17　｜　阶段：M5　｜　状态：已实现（管理页为列表 + 只读详情）

## 1. 需求

选做 1：可将特定用户设为管理员；管理员有独立界面查看所有用户信息（用户名、分析任务数量等），并能查看所有用户的分析任务及其时间线摘要与报告。

## 2. 方案

- 接口（均需 `require_admin`）：
  - `GET /api/admin/users` → 用户列表：id、用户名、角色、文档数、任务数、最近活跃时间
  - `PATCH /api/admin/users/{id}` → 改角色（`user` ↔ `admin`），禁止把自己降级为最后一个管理员
  - `POST /api/admin/users` → 新建普通用户（演示多用户用）
  - `GET /api/admin/tasks?user_id=` → 全量任务
- 页面 `/admin`：上方用户表（角色可切换）、下方任务表；点击任务以只读方式打开该用户的报告与时间线（复用 PLAN 7/8 的渲染组件，编辑与保存按钮隐藏）。
- 另加「系统设置」页：大模型（base_url / model / key / 温度 / 超时）与本地解析器（mineru 路径 / 后端 / 设备 / 权重目录），配「测试大模型」「检测解析器」两个按钮（详见 PLAN_12）。
- 普通用户不显示管理入口，直接访问返回 403。

**实现偏差**：只读详情用「摘要 + 事件列表 + 服务端渲染的报告」展示，未复用主时间线的水平轴组件；权限与数据范围按本计划执行。

## 3. 文件

- 新增 `app/api/admin.py`、`web/admin.html`、`web/views/admin.js`。
- 修改 `web/app.js`（导航按角色显示）、`app/main.py`。

## 4. 验证

1. admin 登录后能看到 demo 用户的文档数与任务数，且数字与库中一致。
2. 点击他人任务能看时间线与报告，但页面无编辑、无保存。
3. demo 用户登录看不到管理入口，直接访问 `/api/admin/users` 返回 403。
4. 把 demo 升为 admin 后重新登录，能看到管理入口。

## 5. 回退

删除 `admin.py`、`admin.html`、`admin.js`，`users.role` 字段保留（普通用户全为 user），不影响基本要求。
