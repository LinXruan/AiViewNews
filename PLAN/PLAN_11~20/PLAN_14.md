# PLAN 14 — AiViewNews：登录注册、双层历史与阅读工作台

日期：2026-11-18　｜　内部版本：103（不在界面显示）　｜　状态：已实现并验证

## 1. 目标

把当前“顶部导航 + 五区页面”改成 **AiViewNews** 的三栏阅读工作台：

- 初始页恢复登录，并支持注册；同时保留“不登陆”入口。
- 登录后进入类似 ChatGPT/DeepSeek 的界面，但没有大对话框。
- 左侧历史栏管理“大历史”；侧栏 2 管理“小历史”（查询记录）与时间线。
- 右侧主区显示 PDF 上传入口或 mineru 的 Markdown 正文。
- PDF 不长期保存；mineru 输出、模型返回、事件和报告都保留。
- 不做暗夜模式，不显示版本号。

## 2. 现状

- 本地数据库：`data/db.sqlite3`，SQLite，启动自动建表。
- 已有 7 张表：`users / documents / tasks / task_documents / events / reports / settings`。
- 当前 PDF 长期留在 `data/uploads`，需要改为临时文件。
- 当前已有 guest 免登录机制（PLAN 13），本计划把界面称呼改为“不登陆”。

## 3. 历史的两层结构（核心）

### 3.1 大历史

- 一条大历史 = 一次 PDF 上传集合（可含多个 PDF）。
- 标题取第一个 PDF 的 `full.md` 中第一个非空正文行（通常是文档标题，不一定是 Markdown 标题）；跳过纯页码，截断到 60 字。
- 只有**所有 PDF 都解析完成（或失败）后**，大历史才出现在左侧历史栏。
- 上传中途被打断时，不占用历史列表，避免 UI 出现空记录或错误状态。

### 3.2 小历史（记录）

- 一条小历史 = 对大历史下的 PDF 做一次查询。
- 当前 `tasks` 表就是小历史：query、状态、时间线摘要、事件、报告。
- 同一套 PDF 可以产生多条小历史。
- 侧栏 2 顶部的 `记录` 按钮用于展开/收起当前大历史的小历史列表。
- 点击某条小历史，右侧时间线和底部简介切换到该次查询结果，不跳页。
- 新建查询会产生新的小历史，完成后自动出现在记录列表并成为当前选中项。

## 4. 页面结构

### 4.1 登录页 / 注册页

- 白色主题，参考 `sources/1.png` 的居中卡片布局。
- 品牌：**AiViewNews**，替换 DeepSeek 字样/标志。
- 登录：用户名、密码、登录按钮、错误提示。
- 注册：用户名、密码、确认密码、注册按钮；样式与登录页一致。
- 登录/注册页互相切换。
- 底部操作：`不登陆`（进入免登录模式）。
- 没有管理员时，提供“创建管理员”入口。
- 不显示版本号。
- 注册成功即自动登录；注册用户角色为普通用户。

### 4.2 登录后的三栏

```
┌────────────┬──────────────┬─────────────────────────────┐
│ 历史栏      │ 侧栏 2        │ 右侧主区                     │
│ AiViewNews │ 记录 / 收起   │ 上传 PDF 或 Markdown 正文     │
│ 搜索        │ 询问框 + ▶    │                             │
│ 大历史列表  │ 小历史记录     │                             │
│ 用户/设置   │ 时间线        │ 底部事件简介（可收起）         │
└────────────┴──────────────┴─────────────────────────────┘
```

#### 历史栏（默认展开）

- 顶部：AiViewNews、搜索按钮、收起/展开按钮。
- 搜索：点击展开输入框，检索**大历史标题**与**小历史 query**；命中后保留对应大历史。
- 大历史列表：标题 + 最近时间；当前项高亮。
- 左下角：头像占位 + 用户名；点击向上弹出：
  - 退出
  - 设置
- 设置面板本期只做：
  - 修改密码
  - 注销账号（删除该用户所有文档、历史、任务、事件、报告，并删除账号）
- “不登陆”用户的用户名显示为“不登陆”。

#### 侧栏 2（大历史可用后出现）

- 出现条件：大历史所有 PDF 进入终态且至少有一份解析成功。
- 顶部右侧：`记录` + 收起/展开按钮。
- 询问框：多行输入，右下角方形按钮，图标为朝右三角。
- **不支持回车提交**；Enter 只换行。
- 点击后图标变正方形，表示正在运行，按钮禁用，不跳页。
- 询问框下方：
  - `记录` 展开时：小历史列表（query + 状态 + 时间）。
  - 时间线：当前小历史的事件节点，日期 + 较短摘要（不必极短，约 20–35 字）。
- 时间线点击逻辑见 §4.3。

#### 右侧主区

- 未上传：大号 PDF 上传按钮/拖拽区。
- 上传中：显示上传与解析进度；**不创建可见历史**。
- 解析完成：左侧出现大历史；右侧显示 Markdown 正文。
- 正文右上角：`保存` 按钮，跳转现有报告保存页。
- 正文下方：事件简介块，默认隐藏，固定高度（约 180–220px），超出滚动。
- 点击时间线节点：
  - Markdown 自动滚动到事件偏移并标黄；
  - 底部简介展开，显示该事件完整说明。
- 再次点击同一节点：
  - 底部简介收起；
  - 标黄保留。
- 点击其他节点：替换为新高亮，简介更新。

## 5. 上传与 PDF 留存

- 上传文件先落到临时目录，仅用于 mineru 解析。
- 解析成功或失败后都删除 PDF 文件。
- 数据库不保存 PDF 二进制；`documents.stored_path` 在删除后置空。
- 保留：
  - `full.md`
  - `page_offsets`
  - 抽取的图片
  - `events`
  - `reports`
  - 模型调用日志
- mineru 自身的 doclib 缓存也要清理：解析后调用 `mineru forget`，或为子进程隔离临时 `MINERU_HOME` 并在结束后删除。
- “不登陆”用户的大历史、小历史、Markdown、图片、事件、报告在 24 小时后自动删除；登录用户长期保留。
- 清理任务每小时运行一次，启动时也执行一次。
- “不登陆”数据不会自动迁移到新注册账号，避免共享数据串号。

## 6. 数据模型

新增：

```sql
histories(
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL CHECK (status IN ('draft', 'ready', 'failed')),
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  published_at TEXT,
  expires_at TEXT
)
```

修改：

- `documents.history_id` → `histories(id)`。
- `tasks.history_id` → `histories(id)`，`tasks` 即小历史。
- `documents.stored_path` 允许为空；增加 `pdf_purged_at`。
- 大历史 `draft` 状态不出现在列表；所有文档终态后写标题、`published_at`，改为 `ready/failed`。
- 删除大历史时级联删除文档、小历史、事件、报告；同时删除 `data/parsed/<doc_id>`。
- 旧数据迁移：本次直接清空旧文档、任务、事件、报告与解析产物；**保留 users 与 settings**，已有账号和 API Key 配置不丢。

## 7. 接口

- `POST /api/register`：注册普通用户并自动登录。
- `POST /api/login` / `POST /api/logout`：保留。
- `GET /api/histories?q=`：大历史列表 + 搜索。
- `GET /api/histories/{id}`：大历史详情、文档、小历史列表。
- `DELETE /api/histories/{id}`：删除大历史及全部关联数据。
- `POST /api/documents`：上传 PDF；归属当前大历史或创建 draft 大历史。
- `POST /api/tasks`：新增小历史（query），归属 `history_id`。
- `GET /api/tasks?history_id=`：大历史下的小历史记录。
- `PATCH /api/me/password`：修改密码。
- `DELETE /api/me`：注销账号并删除全部数据。
- `GET /api/setup/status` / `/api/setup/admin`：保留。
- 现有文档、任务、报告接口继续使用，增加 history 过滤。

## 8. 标题与搜索

- 解析完成时提取标题，不做额外 LLM 调用：
  1. 第一个 PDF 的 `full.md` 第一个非空正文行（通常是文档标题）；
  2. 跳过纯页码行；
  3. 再没有用文件名去扩展名。
- 标题只在首次发布时确定，避免后续查询导致标题漂移。
- 搜索：
  - 大历史标题 LIKE；
  - 或存在 `tasks.query LIKE`；
  - 返回大历史，并可在前端显示命中的 query 片段。

## 9. 账号

- 注册：用户名 3–32 位、密码至少 6 位、唯一。
- 修改密码：验证旧密码，写入新哈希。
- 注销账号：
  - 二次确认；
  - 删除该用户所有大历史、文档、小历史、事件、报告、解析目录；
  - 删除用户记录；
  - 清空会话，回到登录页。
- 最后一个管理员注销需阻止，避免系统没有管理员。
- “不登陆”用户没有密码/设置入口，只显示“不登陆”。
